# appstore/ — App Store 발매판 (iOS · iPadOS)

마지막에 낸다. 애플은 준비물이 더 많고(맥·Xcode·연 $99), 심사에서 "웹사이트를
그대로 감싼 앱"을 가장 싫어하기 때문이다. 그래서 **안드로이드에서 검증된 것을
그대로 가져가는 순서**로 간다.

| 파일 | 무엇 |
|---|---|
| `README.md` | 이 문서 — 폴더의 역할과 지금 상태 |
| `docs/appstore_plan.md` | 심사 요건·빌드 계획·체크리스트 |
| `ios/` | iOS 껍데기(WKWebView)를 여기에 만든다 — 아직 비어 있음 |

## 원칙

- 원본 코드는 **읽기만** 한다. 웹앱은 `play/playstore/scripts/build.mjs` 조립물을 쓴다.
- 심사에서 "최소 기능(4.2)"으로 반려되지 않으려면, 앱 안에서 **기기에서 실제로
  도는 기능**이 보여야 한다. 이 앱은 그게 이미 있다 — 논문·필기는 기기 안에서
  저장되고, 오프라인에서도 열린다. 심사 노트에 이 점을 적는 것이 핵심이다.
- iOS 는 TWA 같은 표준이 없다. WKWebView 껍데기를 직접 만들거나 Capacitor 를 쓴다.
- 도메인·번들 이름은 `site.mjs`(루트) 한 곳에서 온다.

## 지금 상태

- 뼈대만 있음(폴더·계획). 빌드는 **맥 + Xcode** 가 필요해 이 개발 환경에서는 못 한다.
- 안드로이드(플레이) 발매가 끝난 뒤에 착수한다.
